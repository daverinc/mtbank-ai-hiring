## Описание проекта

Pipeline принимает аудиозапись звонка и выполняет полный цикл анализа:

1. **Транскрибация** и диаризация речи (`faster-whisper` + `pyannote`)
2. **Классификация** обращения (тема + приоритет)
3. **Оценка качества** обслуживания по чек-листу
4. **Проверка compliance**
5. **Суммаризация** и формирование рекомендаций

## Оценка качества ASR (WER)

Для оценки качества транскрибации использовалась модель `faster-whisper medium`.

WER рассчитывался с помощью библиотеки `jiwer` путём сравнения распознанного текста с эталонными транскриптами.

| Файл                  | Длительность | Sample Rate | Тип                  | WER (%) | Комментарий                          |
|-----------------------|--------------|-------------|----------------------|---------|--------------------------------------|
| `call_01_dialog.wav`  | 2:16         | 16 kHz      | Диалог (2 спикера)  | 12.4%   | Основной тестовый файл               |
| `call_02_8khz.wav`    | 2:16         | 8 kHz       | Телефонный (8kHz)    | 24.7%   | Значительное ухудшение качества      |
| `call_03_mono.wav`    | 0:42         | 16 kHz      | Монолог              | 8.9%    | Чистая речь                          |
| `call_04_mono.wav`    | 0:38         | 16 kHz      | Монолог              | 11.2%   | —                                    |
| `call_05_mono.wav`    | 0:45         | 16 kHz      | Монолог              | 15.6%   | С небольшим фоновым шумом            |
| **Средний WER**       | —            | —           | —                    | **14.6%** | —                                  |

### Примечания

- Модель: `faster-whisper medium`
- Библиотека для расчёта: `jiwer`
- Самое сильное ухудшение качества наблюдается на файле с телефонным качеством (`call_02_8khz.wav`).
- Средний WER по всем файлам составляет **14.6%**, что является приемлемым результатом для открытой модели.

### Как считается WER

WER рассчитывается по формуле:

$$
WER = \frac{S + D + I}{N} \times 100\%
$$

Где:
- **S** (Substitutions) — замены слов
- **D** (Deletions) — пропущенные слова
- **I** (Insertions) — лишние слова
- **N** — общее количество слов в **эталонном** тексте

### Пример

**Эталонный текст:**
> Добрый день, я хочу узнать про кредит

**Распознанный текст:**
> Добрый день я хочу узнать кредит наличными

| Ошибка       | Количество | Пример                     |
|--------------|------------|----------------------------|
| Замены (S)   | 0          | —                          |
| Удаления (D) | 1          | пропущено слово "про"      |
| Вставки (I)  | 1          | добавлено "наличными"      |
| Всего слов (N) | 7       | —                          |

**WER** = (0 + 1 + 1) / 7 = **28.6%**

### Интерпретация значений WER

| WER          | Качество распознавания     | Комментарий                     |
|--------------|----------------------------|---------------------------------|
| 0–10%        | Отличное                   | Очень хорошая модель            |
| 10–20%       | Хорошее                    | Приемлемо для большинства задач |
| 20–30%       | Среднее                    | Нормально для телефонной речи   |
| 30–50%       | Плохое                     | Требует улучшения               |
| > 50%        | Очень плохое               | Модель почти не работает        |

## Запуск проекта

### 1. Клонирование и настройка

```bash
git clone <repo>
cd mtbank-ai-engineer-test

cp .env.example .env
# Заполни .env (API ключи, HF_TOKEN и т.д.)
```

### 2. Запуск через Docker

```bash
docker compose up -d
```

### 3. Скачивание модели (Ollama)

```bash
docker exec -it ollama_local ollama pull qwen2.5:32b
```

### 4. Запуск Pipeline

Pipeline автоматически подхватывается OpenWebUI после запуска контейнеров.

## Обоснование архитектурных решений

- **LangGraph** выбран для оркестрации агентов, так как обеспечивает явное управление потоком и состоянием.
- **Groq** используется как основной провайдер LLM из-за высокой скорости и качества.
- **faster-whisper + pyannote** — оптимальное open-source решение для русскоязычной диаризации.
- **OpenWebUI Pipelines** — обязательное требование заказчика.
